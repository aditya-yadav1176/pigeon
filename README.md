# Remix of Pigeon Drop

Build a highly polished, production-quality responsive web experience for a product called PIGEON.

IMPORTANT:

This is NOT a generic file-sharing SaaS.

Do NOT make it look like Dropbox, Google Drive, WeTransfer, Notion, Linear, or a typical AI SaaS landing page.

The product should feel like a distinctive, modern consumer internet brand designed for college students.

==================================================

THE PRODUCT

==================================================

PIGEON solves a very specific everyday problem:

A student has something on their PHONE and needs it on their LAPTOP / PC.

Examples:

- Assignment PDF on phone → college lab PC

- PPT on phone → classroom digital board

- Image on phone → friend's laptop

- Video on phone → PC

- Text / URL on phone → laptop

They don't want to:

- log into WhatsApp

- log into Gmail

- send the file to themselves

- create an account

- install an application

- use a USB drive

Pigeon makes this:

OPEN → DROP → QR → SCAN → DONE

The primary use case is:

PHONE → LAPTOP / PC

The secondary direction is:

PC / LAPTOP → PHONE

The platform should also support:

- phone → phone

- PC → phone

- PC → PC

==================================================

CORE BRAND IDEA

==================================================

The name is PIGEON.

The metaphor:

A pigeon carries something from one place to another.

But DO NOT create a childish cartoon pigeon.

The pigeon should become a subtle visual identity.

Think:

- clever

- minimal

- slightly weird

- memorable

- geometric

- friendly

- contemporary

Create a simple pigeon symbol that could work as:

- logo

- favicon

- app icon

- loading animation

- empty state

- QR sharing animation

- tiny decorative element

The pigeon should NOT dominate every screen.

==================================================

TYPOGRAPHY

==================================================

Typography is one of the most important parts of the design.

Use large, confident typography.

Headlines should occupy significant visual space.

Use a strong modern grotesk/sans-serif for the main interface.

You may introduce a tasteful editorial serif for selected marketing statements.

Do NOT make everything small.

Do NOT create the typical SaaS hierarchy:

tiny eyebrow

medium heading

small paragraph

blue button

Instead, use expressive editorial composition.

Examples of possible hero copy:

"Get it off your phone."

"Your phone has it.

Your laptop doesn't."

"Send it across."

"Drop it here.

Pick it up there."

"Why email yourself?"

Choose ONE strong direction and make it visually powerful.

==================================================

COLOR

==================================================

Do not use the standard SaaS blue/purple gradient.

Use a warm off-white / paper-like base.

Primary typography:

deep navy / almost black

Then establish a distinctive Pigeon accent palette.

Potential colors:

- warm yellow

- coral

- cobalt/electric blue

- soft lavender

- fresh green

BUT:

Do not use all colors equally.

Choose ONE dominant brand accent and use the others as occasional visual highlights.

Color should appear intentionally, almost like a poster or editorial design system.

==================================================

LANDING PAGE

==================================================

The first screen should immediately communicate:

"I have something on my phone."

"I want it on my laptop."

"Pigeon gets it there."

Do NOT create a traditional SaaS hero with a huge product screenshot floating inside a gradient.

Instead create an expressive visual composition.

Possible composition:

Large headline on one side.

A stylized PHONE illustration on the other.

A small PIGEON carrying a file from the phone toward a LAPTOP.

The upload interaction should be integrated naturally into this composition.

==================================================

PRIMARY ACTION

==================================================

The primary action is not "Sign Up".

There is NO login.

There is NO registration.

There is NO onboarding.

There is NO dashboard-first experience.

The first interaction should be:

DROP SOMETHING

Large upload area:

"Drop anything here"

Supported:

PDF

PPT

IMAGE

VIDEO

TEXT

Secondary:

"Choose files"

And:

"Paste text"

Small reassurance:

No account required.

Temporary sharing.

==================================================

MAKE THE UPLOAD UI BEAUTIFUL

==================================================

Do not make the upload zone look like a generic rectangular SaaS component.

Experiment with:

- asymmetric composition

- oversized typography

- subtle pigeon illustration

- paper/card elements

- playful file icons

- handwritten/editorial accents

- subtle motion

- unexpected shapes

But keep the actual interaction extremely simple.

The visual design can be expressive.

The UX must remain obvious.

==================================================

THE MAGIC MOMENT: QR

==================================================

After uploading, create a temporary room.

This is the most important product moment.

Screen:

"Your Pigeon is ready."

Show a LARGE QR code.

Below:

"Scan this from your laptop."

Example:

pigeon.app/r/8X29K

Actions:

[ Copy link ]

[ Share ]

Show expiry:

Expires in 09:42

The QR screen should feel like a branded experience.

Do not simply put a QR code inside a generic white card.

Create a visual relationship between:

PHONE → PIGEON → QR → LAPTOP

For example, the pigeon could visually carry the uploaded file toward the QR.

==================================================

RECEIVER EXPERIENCE

==================================================

The laptop opens the temporary room.

Do not show a dashboard.

Do not ask for login.

Do not ask for registration.

Show:

"Someone sent you something."

Then the file.

Example:

┌──────────────────────────────┐

presentation.pptx

24.8 MB

[ Open ] [ Download ]

└──────────────────────────────┘

For multiple files:

DBMS Notes.pdf

Presentation.pptx

diagram.png

lecture-video.mp4

[ Download all ]

The receiver experience should be extremely clean.

==================================================

MOBILE EXPERIENCE

==================================================

Mobile is the PRIMARY device for the sender.

Design mobile FIRST.

The student should be able to:

Open website

↓

Select file

↓

Upload

↓

Show QR

↓

Scan from laptop

↓

Done

The mobile UI must have:

- large touch targets

- minimal navigation

- fast interactions

- obvious upload action

- QR sharing screen

- file preview

- upload progress

Do not cram desktop UI into a mobile screen.

==================================================

DESKTOP EXPERIENCE

==================================================

Desktop is primarily the RECEIVER.

Optimize it for:

- college lab PCs

- personal laptops

- classroom digital boards

Make important actions large enough to be understood quickly.

The receiver should immediately understand:

"This file came from another device."

==================================================

PHONE → PC SHOULD BE THE HERO

==================================================

Do not design the product as an equal file-transfer tool in the first impression.

The main marketing story is:

PHONE → PC

For example:

PHONE

📱

assignment.pdf

      🕊️

             💻

             LAPTOP

             assignment.pdf

The secondary direction can appear later:

"Need to send something back?"

ILLUSTRATION STYLE

==================================================

Create a consistent illustration language.

The pigeon should be:

- simple

- geometric

- slightly abstract

- expressive through shape rather than facial detail

- usable in monochrome

- usable in brand colors

Do not use generic stock illustrations.

Do not use realistic pigeons.

Do not make it look like a children's education app.

==================================================

MOTION

==================================================

Use subtle, purposeful motion.

Examples:

When a file is uploaded:

FILE → PIGEON → QR

When receiver connects:

QR → DEVICE CONNECTED

When download completes:

Pigeon lands / file arrives.

Use:

- smooth transitions

- subtle spring animation

- hover movement

- file movement

- QR reveal

Avoid excessive animations that make the page slow.

==================================================

RESPONSIVE DESIGN

==================================================

Create BOTH:

Mobile

Desktop

Mobile should feel intentionally designed.

Desktop should feel intentionally designed.

Do not simply scale the desktop layout down.

5. QR sharing room

6. Waiting for receiver

7. Receiver connected

8. File received

9. Downloading

==================================================

TECHNICAL DIRECTION

==================================================

Build the frontend as a responsive modern web application.

Use:

React

TypeScript

Tailwind CSS

Keep components modular and reusable.

Prepare the architecture so temporary rooms and file storage can later be connected to a backend such as Supabase.

For now, focus heavily on the FRONTEND EXPERIENCE and visual quality.

Do not create fake complicated backend functionality just to make the UI appear functional.
